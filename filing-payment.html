Applied machine learning · Risk analytics

Predicting filing and payment outcomes with ensemble learning.

A tax-compliance classification case study exploring how structured obligation data, careful feature preparation, chronological validation, and blended model probabilities can support risk-aware prioritization.

01 · The business problem

Revenue and compliance teams need to decide which obligations may need earlier attention. This project explores whether a model can estimate the probability of different filing and payment outcomes, helping an analyst prioritize follow-up rather than treating every case identically.

Intended use: decision support for analysts. A predicted risk class is not proof of future behaviour and should never be treated as an automatic enforcement decision.

02 · Data preparation and leakage awareness

The workflow loads local CSV files, checks their dimensions and labels, and uses only features shared by the training and test sets. It excludes identifiers, target columns, and potential filing/payment outcome-date fields from the predictor set.

  • Derives year, month, day, and weekday from start, end, and obligation due dates.
  • Creates period-length and end-to-due-date interval features.
  • Imputes missing predictor values and one-hot encodes categorical variables.
  • Aligns class-probability columns before scoring and submission generation.

03 · Baseline versus taxpayer-history features

Baseline · implemented

Common taxpayer and obligation attributes plus engineered calendar and date-interval features. This is what the currently checked-in notebook can reproduce.

History-enhanced · explored separately

Prior-only behaviour features such as historical on-time rates, late-payment patterns, and previous obligation counts. The history pipeline must be restored and rerun before claiming a performance uplift.

For a fair comparison, both feature sets must use the same chronological holdout and only information available before each prediction point. Historical outcomes from the current or future obligation must never leak into its features.

04 · Model comparison and ensemble design

Extra Trees

A bagging-based tree ensemble used to capture nonlinear patterns and interactions.

XGBoost and CatBoost

Boosted-tree approaches compared with Extra Trees. Each produces class probabilities for probability-based evaluation and potential blending.

The notebook uses chronological validation and searches non-negative blend weights. Probability alignment and normalization are checked before log-loss evaluation. A more complex ensemble is only useful if it improves reliable out-of-time validation.

06 · Limitations and responsible use

  • Class imbalance and missing target labels affect effective sample sizes and make per-class metrics important.
  • Taxpayer behaviour can change over time, so temporal backtesting is essential.
  • The configured validation cutoff must be checked against the true data timeline.
  • The current notebook does not reproduce the earlier taxpayer-history feature pipeline.
  • This is a research/competition workflow, not a deployed tax system. Production use would need monitoring, privacy safeguards, governance, and human review.
